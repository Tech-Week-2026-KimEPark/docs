# 탐색 개선 설계

이 문서는 미션 탐색(EXPLORE)이 방 안의 사과를 놓치는 문제의 원인 측정과 개선 설계를 정리합니다. 개선 항목은 6개이며 이 문서는 첫 항목인 이동 중 둘러보기의 상세 설계를 포함합니다. 나머지 항목은 설계를 마치는 대로 이 문서에 추가하십시오. 구현 후에는 [mission 기능 문서](features/mission.md)와 [planner 기능 문서](features/planner.md)에 반영하십시오.

## 1. 문제

Webots 연습 맵에서 로봇이 방에 들어가지 않거나, 방에 들어가도 방 안의 사과를 찾지 못하는 경우가 많다는 보고가 있었습니다. 현재 탐색은 라이다 격자 지도의 프론티어를 목표로 이동하고, 프론티어가 없으면 복귀합니다.

- 프론티어: 라이다로 확인한 빈칸 중 모르는 칸과 맞닿은 칸
- 라이다: 360°, 최대 3.5 m
- 카메라: 앞쪽 수평 화각 60°. 사과 검출 거리는 색 분할 기준 약 5 m

탐색 종료 조건은 라이다 지도가 채워졌는지만 봅니다. 카메라가 실제로 바닥을 봤는지는 확인하지 않습니다. 로봇이 문 앞을 지나며 라이다가 방 안을 채우면 그 방에는 프론티어가 남지 않습니다. 이때 카메라가 복도 방향을 보고 있었다면 방 안의 사과는 검출되지 않습니다.

## 2. 현재 탐색 측정

### 2.1 측정 방법

`apartment.wbt`의 벽 27개, 창문 8개, 출입문 1개로 2차원 맵을 만들고 sar-robot `main`(`199349b`)의 `Mission`을 제한 시간까지 실행했습니다. 장치는 다음과 같이 대체했습니다.

| 장치 | 대체 방법 |
|---|---|
| 라이다 | 벽 선분에 대한 광선 추적. 360개, 0.12~3.5 m |
| 나침반 | Webots 규약(원시각 = π/2 − 방향)으로 계산 |
| 카메라 | 빨간 사과를 투영해 원으로 그림. 벽에 가리면 그리지 않음 |
| 바퀴 | 속도 명령대로 이동. 벽과 로봇 반지름 이내로 가까워지면 이동하지 않음 |
| 검출 | YOLO 없이 색 분할만 사용 |

가구, 보행자, 바퀴 미끄러짐에 의한 위치 추정 오차는 반영하지 않았습니다. 따라서 이 측정은 실제 맵보다 유리한 조건입니다.

사과 배치는 2가지입니다.

| 경우 | 빨간 사과 위치 |
|---|---|
| 연습 맵 | (−12.02, −3.02), (−5.34, −10.54) |
| 안쪽 방 | (−1.6, −11.8), (−8.9, −7.7). 연습 맵 실행에서 로봇이 들어가지 않은 방 |

### 2.2 결과

| 항목 | 연습 맵 | 안쪽 방 |
|---|---|---|
| 전체 시간 | 373초 | 584초 |
| EXPLORE 시간 | 238초 | 376초 |
| EXPLORE 주행 거리 | 39.9 m | 60.6 m |
| 목표 변경 | 41회 | 84회 (평균 4.5초마다) |
| 되돌아감 (A→B→A 목표) | 측정 안 함 | 9회 |
| 프론티어 목표 도착 | 0회 | 0회 |
| 사과 첫 검출 가능 시각 | 64초, 288초 | 218초, 426초 |
| 블랙리스트 | 없음 | 오른쪽 위 방 문 앞 (−3.57, −3.02). 30초 제한 초과 |

두 경우 모두 사과 2개를 구조했습니다. 확인한 문제는 다음과 같습니다.

- 연습 맵 실행에서 오른쪽 아래 방은 라이다로만 확인되고 카메라는 보지 않았습니다. 사과가 그 방에 있었다면 늦게 찾거나 놓쳤을 것입니다.
- 안쪽 방 사과를 처음 볼 수 있었던 시각은 426초입니다. 제한 시간 900초에서 복귀 예비 150초를 빼면 750초 안에 찾아야 하므로 여유가 적습니다.
- 프론티어 목표에 한 번도 도착하지 않았습니다. 목표를 2초마다 다시 고르고, 로봇이 다가가면 라이다가 앞을 채워 프론티어가 뒤로 물러나기 때문입니다.
- 오른쪽 위 방 문 앞 목표는 30초 안에 도달하지 못해 블랙리스트에 올랐고, 이후 그 방에 들어가지 않았습니다.
- 시작점 (−0.3, −7.5)은 출입문 벽에서 0.15 m 떨어져 있어 벽 팽창 영역 안입니다. 복귀 마지막 구간에서 4초 정체와 RECOVERY가 반복됩니다.

## 4. 이동 중 둘러보기

탐색 중 새 공간에 들어섰을 때 제자리에서 1회전해 카메라로 주변을 확인합니다.

### 4.1 시작 조건

처음에는 프론티어 목표에 도착했을 때 둘러보는 방식을 검토했습니다. 2.2절 측정에서 도착이 0회였으므로 이 조건은 동작하지 않습니다. 대신 다음 두 조건을 측정했습니다.

| 시작 조건 | 둘러보기 횟수 (연습 맵 / 안쪽 방) | 추가 시간 (1회 7.9초) |
|---|---|---|
| 프론티어 목표 도착 | 0 / 0 | 0초 |
| 이동 거리 2 m마다 | 19 / 30 | 150 / 236초 |
| 이동 거리 3 m마다 | 13 / 20 | 103 / 158초 |
| 이동 거리 4 m마다 | 9 / 15 | 71 / 118초 |
| 문 통과 | 6 / 8 | 47 / 63초 |
| 문 통과, 같은 곳 반복 제외 (1.5 m) | 4 / 5 | 31 / 39초 |

문 통과는 라이다 좌우 거리로 판정합니다. 왼쪽(인덱스 80~100)과 오른쪽(인덱스 260~280) 최솟값의 합을 통로 폭 $w$로 둡니다.

- $w <$ `DOOR_WIDTH_IN`(1.2 m)이면 좁은 통로 안으로 판정
- 좁은 통로 안에서 $w >$ `DOOR_WIDTH_OUT`(2.0 m)이 되면 넓은 공간에 들어선 것으로 보고 둘러보기 시작

두 기준을 다르게 두어 문틀 근처에서 판정이 흔들리지 않게 합니다. 측정에서 같은 문 주변 판정이 여러 번 나왔으므로, 이전 둘러보기 위치에서 `LOOK_MIN_SPACING`(1.5 m) 이내이면 생략합니다.

제안하는 시작 조건은 다음과 같습니다.

1. 주 조건: 문 통과
2. 보조 조건: 마지막 둘러보기 뒤 EXPLORE 주행 거리가 `LOOK_DISTANCE`(4 m) 이상. 문 없이 넓게 트인 공간 대비
3. 공통 제외: 이전 둘러보기 위치에서 `LOOK_MIN_SPACING` 이내, 또는 남은 시간이 `RETURN_RESERVE` + 둘러보기 1회 시간 미만

주 조건만 쓰면 연습 맵 기준 추가 시간은 약 30~40초입니다. 보조 조건을 더하면 늘어나므로, 구현 후 측정해 `LOOK_DISTANCE`를 조정하십시오.

### 4.2 동작

새 상태 LOOK_AROUND를 추가합니다.

| 단계 | 동작 |
|---|---|
| 진입 | EXPLORE 중 시작 조건 충족. 현재 위치를 둘러보기 위치 목록에 추가 |
| 회전 | `LOOK_W`(0.8 rad/s)로 제자리 좌회전. 누적 회전량은 INIT_SPIN과 같이 나침반 원시각 변화로 계산하고, 나침반이 없으면 오도메트리 방향 변화 사용 |
| 검출 중 정지 | 검출 결과가 있으면 회전을 멈추고 검출 방향으로 정렬. 최대 `LOOK_PAUSE`(1.5초) |
| 종료 | 누적 회전량 2π 이상 → EXPLORE (경로 재계획). 대상 확정 → APPROACH. 제한 시간 `LOOK_TIMEOUT`(회전 시간의 2배) 초과 → EXPLORE |

인식은 LOOK_AROUND에서도 실행해야 합니다. 현재 `Mission.tick()`은 INIT_SPIN, EXPLORE, APPROACH에서만 인식을 실행하므로 상태 목록에 LOOK_AROUND를 추가합니다.

검출 중 정지가 필요한 이유는 연속 확인 조건 때문입니다. 대상이 화각 $\phi_h$ 안에 머무는 시간 $t_{\text{view}}$와 그 동안의 YOLO 실행 횟수 $n$은 다음과 같습니다.

$$
t_{\text{view}} = \frac{\phi_h}{\omega_{\text{look}}} = \frac{1.047}{0.8} \approx 1.31\ \text{s}, \qquad
n = \frac{t_{\text{view}}}{4 \times 0.064\ \text{s}} \approx 5.1
$$

분모의 4는 YOLO 실행 주기(`YOLO_EVERY`), 0.064 s는 step 간격입니다. `CONFIRM_FRAMES`는 4입니다. 색 분할은 화면 가장자리에 닿은 덩어리를 제외하므로 실제로 연속 검출되는 횟수는 5회보다 적습니다. 회전을 멈추지 않으면 확정에 실패할 수 있습니다.

### 4.3 시간 비용

| 항목 | 값 |
|---|---|
| 1회 회전 시간 | $2\pi / 0.8 \approx 7.9$초 |
| 연습 맵 추가 시간 (주 조건) | 약 31~39초 |
| 현재 전체 시간 (측정) | 373~584초 |
| 사용 가능 시간 | 750초 (제한 900초 − 복귀 예비 150초) |

둘러보기로 사과를 더 일찍 찾으면 EXPLORE 시간이 줄어 전체 시간은 늘지 않을 수 있습니다. 개선 효과는 미확인이므로 4.6절 방법으로 측정하십시오.

### 4.4 인터페이스와 설정값

인터페이스 변경은 `mission.py` 내부로 한정합니다. 다른 모듈의 함수 형식은 바뀌지 않습니다.

```python
# mission.py
LOOK_AROUND = "LOOK_AROUND"
# EXPLORE 처리 시작 부분에서 시작 조건 검사 → _set_state(LOOK_AROUND, 이유)
# _handlers[LOOK_AROUND] = _look_around
# tick(): 인식 실행 상태 목록에 LOOK_AROUND 추가
# self.look_spots: list[Point]  둘러보기 위치 목록 (LOOK_MIN_SPACING 판정)
# self._since_look: float       마지막 둘러보기 뒤 EXPLORE 주행 거리
# self._in_doorway: bool        문 통과 판정 상태
```

| 설정값 | 제안 값 | 의미 |
|---|---|---|
| `LOOK_W` | 0.8 rad/s | 둘러보기 회전 속도. `INIT_SPIN_W`와 같음 |
| `LOOK_DISTANCE` | 4.0 m | 보조 조건 주행 거리 |
| `LOOK_MIN_SPACING` | 1.5 m | 이전 둘러보기 위치와의 최소 거리 |
| `DOOR_WIDTH_IN` | 1.2 m | 좁은 통로 판정 폭 |
| `DOOR_WIDTH_OUT` | 2.0 m | 넓은 공간 판정 폭 |
| `LOOK_PAUSE` | 1.5 s | 검출 시 회전 정지 최대 시간 |
| `LOOK_TIMEOUT` | 2 × 2π / `LOOK_W` | 둘러보기 제한 시간 |

### 4.5 역할

| 역할 | 범위 |
|---|---|
| 통합 (김태훈) | LOOK_AROUND 상태, 시작 조건, 상태 전환 로그 |
| 인지 (이온규) | 검출 중 정지 조건 확인, 4.6절 가상 맵 측정과 Webots 측정 |
| 계획 (박상원) | 둘러보기 뒤 재계획 확인. 함수 변경 없음 |
| 행동 (김규민) | 제자리 회전 중 안전 필터 동작 확인. 함수 변경 없음 |

### 4.6 검증 계획

2.1절 가상 맵으로 적용 전후를 비교합니다.

| 측정 항목 | 통과 기준 |
|---|---|
| 방마다 사과 1개를 두고 실행 (방 8곳) | 적용 후 사과 첫 검출 시각의 최댓값이 적용 전보다 짧음 |
| 카메라가 본 바닥 면적 / 라이다로 확인한 빈칸 면적 | 적용 후 95% 이상 |
| 둘러보기 횟수와 추가 시간 | 연습 맵 60초 이하 |
| 전체 시간 | 750초 이하 |
| 사과 없는 실행 | 모든 방을 둘러본 뒤 복귀 |

Webots에서는 연습 맵과, 사과를 안쪽 방에 옮긴 월드에서 LOOK_AROUND 진입 위치와 사과 검출 시각을 기록합니다.

### 4.7 미확인 항목

| 항목 | 내용 |
|---|---|
| 실제 맵 문 판정 | 가구·문틀이 있는 Webots 맵에서 통로 폭 판정이 문에서만 발생하는지 미확인 |
| 가구 가림 | 방 안에서 1회전해도 가구 뒤의 사과는 보이지 않음. 방 가운데로 들어가야 하는 경우의 비율 미확인 |
| 보행자 | 회전 중 보행자 등 움직이는 물체가 접근하는 경우의 처리. 움직이는 물체 회피 설계(docs [#21](https://github.com/Tech-Week-2026-KimEPark/docs/pull/21))의 YIELD 상태와 우선순위 정리 필요 |
| 회전 스케일 | 제자리 회전 시 오도메트리 회전량 오차. 나침반이 없으면 1회전 판정이 부정확함 |

### 4.8 구현 결과

sar-robot `feat/look-around` 브랜치에 4.1~4.4절을 구현했습니다. 설정값 `LOOK_AROUND_ENABLED`로 켜고 끕니다. 2.1절 가상 맵에서 같은 main 코드(`ad161d1`)로 켠 경우와 끈 경우를 비교했습니다.

| 사과 배치 | 둘러보기 | 횟수 (시간) | 사과 첫 검출 가능 시각 | 전체 시간 |
|---|---|---|---|---|
| 연습 맵 | 끔 | 0 | 63초, 206초 | 552초 |
| 연습 맵 | 켬 | 5 (40초) | 89초, 249초 | 585초 |
| 안쪽 방 | 끔 | 0 | 33초, 301초 | 694초 |
| 안쪽 방 | 켬 | 9 (71초) | 41초, 394초 | 737초 |

- 벽만 있는 가상 맵에서는 사과 첫 검출이 앞당겨지지 않았습니다. 이 맵에서는 사과가 탐색 경로의 카메라 시야에 들어왔기 때문입니다.
- 카메라가 본 바닥 면적은 안쪽 방 배치에서 119.7 m²에서 124.8 m²로 늘었습니다.
- 둘러보기 시간만큼 전체 시간이 늘어 안쪽 방 배치에서 737초로 사용 가능 시간 750초에 근접했습니다.
- 따라서 기본값은 꺼짐(`False`)으로 두었습니다. 가구로 시야가 가려지는 Webots 연습 맵에서 켜고 비교한 뒤 결정하십시오.

같은 비교에서 복귀(RETURN) 시간이 202~261초로 이전 측정(55~94초)보다 크게 늘었습니다. main `ad161d1`(sar-robot #18 근접 장애물 감속과 통로 양보) 반영 이후의 변화이며 원인은 확인하지 않았습니다.
