# planner 기능 설명

이 문서는 sar-robot `controllers/sar_main/sar/planner.py`에 구현한 A\* 경로 계획, 다익스트라 프론티어 선택, 복귀 비용 지도의 동작, 미션 연결 방법, 검증 결과를 설명합니다.

## 과제와의 관계

| 상태 | 사용 함수 | 역할 |
|---|---|---|
| EXPLORE | `choose_frontier_path()`, `plan()` | 다음 프론티어 선택과 경로 계산 |
| APPROACH | `plan()` | 사과 앞 접근점까지 경로 |
| RETURN | `DistanceField(grid, 시작점)`, `plan(..., field=)` | 시작점까지 경로. 모르는 칸 통과 허용 |
| 공통 안전 규칙 | `DistanceField.distance()`, `path_length()` | 남은 복귀 비용·길이로 강제 복귀 시점 판단 |

## 동작 원리

### 방법 선택

목표가 1개인 계산은 A\*, 목표가 여러 개이거나 여러 지점에서 같은 목표까지의 비용이 필요한 계산은 다익스트라를 사용합니다.

| 계산 | 방법 | 선택 이유 |
|---|---|---|
| 두 지점 경로 `plan()` | A\*, 옥타일 휴리스틱 | 목표 방향 칸만 확장해 확장 칸 수가 가장 적음 |
| 프론티어 선택 `choose_frontier_path()` | 로봇 기준 다익스트라, 조기 종료 | 1회 실행으로 목표 선택과 경로 계산을 함께 수행 |
| 복귀 비용 지도 `DistanceField` | 기준점 다익스트라 | 모든 칸의 복귀 비용과 복귀 경로를 1회 계산으로 확보 |
| A\* 가속 `plan(..., field=)` | 비용 지도를 A\* 휴리스틱으로 사용 | 휴리스틱이 실제 비용에 가까워 확장 칸 수 감소 |

### 격자 그래프와 비용

- 8방향 이동입니다. 직선 이동 거리는 1칸, 대각 이동은 $\sqrt{2}$칸입니다.
- 대각 이동은 양옆 직교 칸이 모두 통과 가능할 때만 허용합니다.
- 통과 가능 칸은 팽창 영역(`blocked`) 밖의 칸입니다. 모르는 칸은 `allow_unknown`이 참일 때만 `UNKNOWN_COST` 배수로 통과합니다.
- 칸 $u$에서 칸 $v$로 이동하는 비용은 이동 거리 $s$와 두 칸의 비용 배수 $c$의 평균의 곱입니다.

$$
w(u, v) = s \cdot \frac{c_u + c_v}{2}, \qquad
c = 1 + k_{\text{wall}} \cdot \operatorname{clip}\left(\frac{R_{\text{inf}} + B - d}{B},\ 0,\ 1\right)
$$

$d$는 장애물 거리, $R_{\text{inf}}$는 `INFLATE`, $B$는 `WALL_BAND`, $k_{\text{wall}}$은 `WALL_COST`입니다. 벽에서 멀수록 배수가 1로 감소하므로 경로가 통로 가운데로 생성됩니다.

팽창 반경이 0.175 m이므로 통과 가능한 최소 통로 폭은 빈칸 7개(0.35 m)입니다. 빈칸 6개(0.30 m) 통로는 통과 불가로 판정합니다.

### 최종 경로의 안전 규칙

탐색, 경로 다듬기, 시작·끝 좌표 교체에 같은 규칙을 적용합니다.

- 경로 선분이 지나가는 칸과 선분이 닿는 칸은 모두 통과 가능해야 합니다.
- 선분이 격자 모서리를 지나면 모서리에 닿는 칸 4개를 모두 검사합니다. A\*의 대각 이동 규칙과 같은 조건입니다.
- 다듬기 전 꺾은선은 `[실제 시작 좌표, 칸 중심들, 실제 끝 좌표]`입니다. 실제 좌표와 칸 중심은 같은 칸 안에 있으므로 이 꺾은선은 규칙을 만족합니다.
- 다듬기는 규칙 검사를 통과한 선분으로만 중간 점을 생략합니다. 검사에 실패하면 원래 점을 유지합니다.
- 다듬은 선분은 생략한 구간의 최대 비용 배수를 넘는 칸을 지나지 않습니다. 다듬기로 경로가 벽에 더 가까워지지 않습니다.

### 시작·목표 대체

시작이나 목표가 통과 불가 칸이면 실제 좌표에서 `SNAP_RADIUS`(0.5 m) 이내 통과 가능 칸을 가까운 순서로 확인해 첫 번째 유효한 칸을 사용합니다.

| 조건 | 정책 |
|---|---|
| 실제 좌표와 대체 칸을 잇는 선분이 장애물 칸을 지나거나 닿음 | 그 칸은 선택하지 않음. 벽 반대편 칸 제외 |
| 실제 좌표가 장애물 칸 안 (지도 오차) | 그 장애물의 연속 구간만 통과 허용. 구간을 벗어난 뒤 다시 장애물 칸을 지나면 무효 |
| 시작점이 팽창 영역 안 | 대체 칸까지의 탈출 구간만 팽창 영역 통과 허용. 시작 위치의 장애물 거리(로봇 반지름 한도)보다 1칸 넘게 가까워지는 칸은 금지 |
| 시작 쪽 탈출 구간의 모르는 칸 | `allow_unknown`이 거짓이면 금지 |
| 목표를 대체 칸으로 옮김 | 경로 끝점은 대체 칸 중심. 끝점을 실제 목표 좌표로 바꾸지 않음 |
| 유효한 대체 칸 없음 | `None` 반환 |

`DistanceField.distance()`와 `DistanceField.path()`도 같은 정책을 사용합니다.

### A\* 휴리스틱과 비용 지도 재사용

비용 배수가 1 이상이므로 옥타일 거리는 실제 비용을 과대평가하지 않습니다. $\Delta r$, $\Delta c$는 목표까지 행·열 차이입니다.

$$
h(n) = \max(\Delta r, \Delta c) + (\sqrt{2} - 1)\min(\Delta r, \Delta c)
$$

`plan(..., field=D)`는 다음 조건을 모두 만족할 때만 $h(n) = \max(h_{\text{oct}}(n),\ D(n))$을 사용합니다. 조건이 맞지 않으면 비용 지도를 무시하고 옥타일 휴리스틱으로 계산합니다.

| 조건 | 이유 |
|---|---|
| 같은 `GridMap` 객체 | 다른 지도의 비용은 의미가 없음 |
| `D.is_current()`가 참 | 장애물·확인 분류나 비용 설정이 바뀌면 비용이 달라짐 |
| 비용 지도의 기준 칸(대체 포함) = 계획 목표 칸(대체 포함) | 다른 기준점의 비용은 휴리스틱 효과가 없음 |
| 비용 지도 영역이 계획 영역을 포함 | 영역 밖 칸은 비용을 조회할 수 없음 |

비용 지도는 모르는 칸 통과를 허용한 그래프의 최단 비용입니다. 계획 그래프는 이 그래프의 부분 그래프이고 공통 간선의 비용이 같습니다. 따라서 $D$는 과대평가하지 않고 단조성을 유지하며, A\* 결과는 최단 비용입니다.

`GridMap.plan_version`은 장애물 여부나 확인 여부가 바뀐 갱신에서만 증가합니다. log-odds 값만 바뀐 갱신에서는 비용 지도와 계획 영역 캐시가 유효합니다. 탐색 중에는 새 칸이 거의 매 스텝 확인되므로 비용 지도는 사용 직전에 생성하십시오.

### 프론티어 선택과 조기 종료

프론티어 칸의 점수는 묶음 칸 수 $N$을 경로 비용 $d$ [m]로 나눈 값입니다. 다익스트라는 칸을 비용 오름차순으로 확정하므로 아직 확정하지 않은 칸의 점수는 $N_{\max} / d_{\text{cur}}$ 이하입니다. 현재 최고 점수가 이 상한 이상이면 탐색을 종료합니다.

$$
\text{score} = \frac{N}{d}, \qquad
\text{stop if } \text{score}_{\text{best}} \ge \frac{N_{\max}}{d_{\text{cur}}}
$$

- $N_{\max}$는 로봇 위치에서 도달 가능한 영역의 프론티어만으로 계산합니다. 도달 가능 영역은 통과 가능 칸의 4방향 연결 영역과 같습니다. 벽 너머의 큰 프론티어 때문에 조기 종료가 늦어지지 않습니다.
- `FRONTIER_MIN_DIST`(0.3 m)보다 가까운 칸과 블랙리스트 좌표에서 `BLACKLIST_RADIUS` 이내 칸은 제외합니다.
- 경로는 같은 다익스트라의 역추적 결과입니다. `plan()`을 다시 호출하지 않습니다.

### 계산 범위와 캐시

- 확인한 영역과 시작·목표를 포함하는 사각형에 `PLAN_MARGIN`(1 m)을 더한 범위만 계산합니다.
- 계획 영역(통과 가능 여부, 비용 배수, 연결 영역)은 `plan_version`이 같은 동안 재사용합니다.
- 시작과 목표가 다른 연결 영역이면 탐색 없이 `None`을 반환합니다.

## 미션 연결 안내

`mission.py`에서 계획 모듈을 호출하는 방법입니다. `mission.py`(sar-robot #13)는 통합 담당 파일이며 이 기능에서 수정하지 않았습니다. #13의 현재 호출 방식과 다른 항목은 "미션 #13과의 차이"에 있습니다.

### 호출 흐름

```python
grid.update(pose, ranges)                      # 매 step

# EXPLORE: 목표가 없을 때만 선택. 목표와 경로를 함께 받음
found = planner.choose_frontier_path(grid, pose, blacklist)
if found is None:
    state = RETURN                             # 도달 가능한 프론티어 없음
else:
    target, path = found

# 같은 목표로 재계획 (2초 주기, 안전 필터 3초 차단, 정체 복구 후)
path = planner.plan(grid, pose[:2], target)

# APPROACH: 사과 중심이 아니라 접근점을 목표로 지정
path = planner.plan(grid, pose[:2], approach_xy)

# RETURN: 비용 지도를 만든 직후 사용
field = planner.DistanceField(grid, start_xy)
path = planner.plan(grid, pose[:2], start_xy, allow_unknown=True, field=field)

v, w, reached = local_control.pure_pursuit(pose, path)
v, w, blocked = local_control.safety_filter(v, w, ranges)
```

### 재계획과 목표 재선택

| 동작 | 호출 | 시점 |
|---|---|---|
| 경로 재계획 | `plan(grid, pose, 같은 목표)` | 2초 주기, 안전 필터가 3초 이상 차단, 정체 복구 후 |
| 목표 재선택 | `choose_frontier_path(grid, pose, blacklist)` | 목표 도착, 재계획 결과 `None`, 30초 안에 미도달(블랙리스트 등록 후) |

목표를 2초마다 다시 선택하면 점수가 비슷한 프론티어 사이에서 목표가 바뀔 수 있습니다. 목표는 유지하고 경로만 재계획하십시오. 탐색 중에는 지도가 매 스텝 바뀌므로 2초 전 경로의 안전은 보장되지 않습니다. 재계획 주기 사이의 충돌 방지는 `safety_filter()`가 담당합니다.

### 반환값의 의미

| 반환 | 의미 | 미션 처리 |
|---|---|---|
| `plan()` → `None` | 경로 없음, 입력이 `None`·NaN·지도 밖, 유효한 대체 칸 없음 | 프론티어 목표이면 블랙리스트 등록 후 재선택. 복귀이면 `allow_unknown=True` 확인 후 정체 복구 |
| `plan()` → 점 1개 | 시작과 목표가 같은 좌표 | 도착 처리 |
| `path[-1] != goal_xy` | 목표가 통과 불가 칸이라 대체 칸 중심에서 끝남 | 실제 목표까지 남은 거리를 미션에서 계산 |
| `choose_frontier_path()` → `None` | 도달 가능한 프론티어 없음 | RETURN 전환 |
| `DistanceField.distance()` → `None` | 기준점에 도달 불가 또는 유효한 대체 칸 없음 | 복귀 비용을 알 수 없음으로 처리 |
| `DistanceField.path()` → `None` | 도달 불가 또는 지도가 바뀜(`is_current()` 거짓) | `plan(..., field=)` 사용 |

계획 함수는 예외를 발생시키지 않고 `None`을 반환합니다.

### 비용과 길이의 구분

- `DistanceField.distance(xy)`는 가중 비용 [m]입니다. 벽 근처와 모르는 칸의 배수가 포함되어 실제 길이 이상입니다.
- 지도가 바뀐 뒤에도 `distance()`는 생성 시점의 값을 반환합니다. 강제 복귀 판단의 근삿값으로 사용할 수 있습니다.
- 복귀 시간 추정에는 `planner.path_length(path)`를 사용하십시오. `path_length(path) / V_MAX`는 회전과 감속을 포함하지 않은 하한입니다.

### 미션 #13과의 차이

| 항목 | 미션 #13의 현재 방식 | 권장 |
|---|---|---|
| 탐색 목표 | 2초마다 `choose_frontier()`로 다시 선택한 뒤 `plan()` 호출 | `choose_frontier_path()` 1회 호출로 목표와 경로를 함께 받음. 목표는 도착·실패 때만 다시 선택 |
| 복귀 | `plan(grid, pose, 시작점, allow_unknown=True)` | 그대로 사용 가능. 복귀 비용 조회가 필요하면 `DistanceField`를 함께 사용 |
| 접근점 | 사과에서 로봇 방향으로 `APPROACH_DIST` 떨어진 점을 목표로 지정 | 그대로 |
| 복귀 도착 | `GOAL_TOL` 이후 `RETURN_TOL`까지 직진 접근 | 그대로 |

기존 호출 형식은 그대로이므로 미션 코드를 수정하지 않아도 동작합니다.

### 미션이 담당하는 항목

- **접근점 계산**: 사과는 라이다 높이보다 낮아 지도에 없습니다. 사과 중심을 목표로 지정하면 경로가 사과 위치까지 이어집니다. 목표는 사과에서 로봇 방향으로 `APPROACH_DIST`(0.35 m) 떨어진 접근점으로 지정하십시오.
- **도착 판정**: `pure_pursuit()`는 경로 끝점에서 `GOAL_TOL`(0.15 m) 이내이면 도착으로 판정합니다. 상태 머신의 복귀 판정은 0.12 m 이내입니다. 합성 주행에서 도착 시 끝점 오차는 0.145 ~ 0.148 m였습니다. 복귀 마지막 구간은 미션에서 0.12 m까지 접근하도록 처리하거나 `GOAL_TOL`을 조정하십시오.
- **지도 직접 수정**: `logodds`나 `seen`을 직접 바꾸면 `grid.invalidate()`를 호출하십시오.
- **시간 관리**: 제한 시간, 블랙리스트, 정체 복구는 미션 상태 머신에서 관리합니다.

## 인터페이스와 설정값

| 함수 | 입력 | 출력 |
|---|---|---|
| `plan(grid, start_xy, goal_xy, allow_unknown=False, field=None)` | 지도, 시작·목표 `(x, y)` | 경로 `[(x, y), ...]`. 없으면 `None` |
| `choose_frontier(grid, pose, blacklist)` | 지도, `(x, y, theta)`, 제외 좌표 목록 | 목표 `(x, y)`. 없으면 `None` |
| `choose_frontier_path(grid, pose, blacklist)` (추가) | `choose_frontier()`와 같음 | `(목표, 경로)`. 없으면 `None` |
| `path_length(path)` (추가) | 경로 또는 `None` | 실제 길이 [m] 또는 `None` |
| `DistanceField(grid, origin_xy)` (추가) | 지도, 기준점 | 비용 지도 객체 |
| `DistanceField.distance(xy)` (추가) | 월드 좌표 | 기준점까지 가중 비용 [m] 또는 `None` |
| `DistanceField.path(xy)` (추가) | 월드 좌표 | 기준점까지 경로 또는 `None` |
| `DistanceField.is_current()` (추가) | 없음 | 생성 이후 계획용 지도 상태 유지 여부 |

기존 `plan()`, `choose_frontier()`의 호출 형식은 그대로입니다.

| 설정값 | 값 | 의미 |
|---|---|---|

### 수정 전 코드에서 재현한 문제

구현과 독립된 검사기(`tests/planner_checks.py`)로 확인했습니다. 검사기는 경로 선분을 2 mm 간격으로 표본화하고, 최단 비용은 별도 다익스트라로 계산합니다.

| 문제 | 수정 전 | 수정 후 |
|---|---|---|
| 다듬기 후 경로가 통과 불가 칸 통과 | 무작위 지도 30개, 경로 113개 중 1개 위반 | 지도 40개, 경로 100개 이상에서 위반 0건 |
| 거리 지도 기준점이 팽창 영역 안일 때 경로 끝점 | 끝점을 팽창 영역 안 좌표로 교체 | 대체 칸 중심에서 종료 |
| 시작점 대체 칸이 벽 반대편 | 벽 반대편 칸 선택 | 같은 쪽 칸 선택. 없으면 `None` |
| 지도 변경 후 오래된 거리 지도의 `path()` | 닫힌 문을 통과하는 경로 반환 (표본 위반 195건) | `None` 반환 |
| 좌표 NaN 입력 | `ValueError` 발생 | `None` 반환 |
| 경로 끝점 좌표 | 부동소수점 오차로 목표와 불일치 가능 | 목표 좌표와 일치 |
| 다른 목표 기준 거리 지도 사용 | 재현되지 않음. 최단 비용 유지 | 사용하지 않음 (휴리스틱 효과 없음) |

다른 목표 기준 거리 지도는 같은 지도에서 삼각 부등식을 만족하므로 최단 비용을 깨지 않습니다. 실제 위험은 지도가 바뀐 뒤의 오래된 거리 지도입니다.

## 한계와 확인 필요 항목

| 항목 | 상태 |
|---|---|
| Webots 주행 (`sar_apartment.wbt`) | 1회 실행에서 미완주. "Webots 실행 결과" 참고 |
| 라이다 높이에서 다리만 보이는 가구 | 몸체가 지도에 없어 경로가 가구 옆을 가깝게 지날 수 있음. 팽창 반경이나 벽 근처 비용 조정 검토 필요 |
| 오도메트리 오차가 있을 때의 경로 추종과 지도 품질 | 미확인. 합성 주행은 오차 없는 위치 사용 |
| 보행자가 있을 때의 재계획 | 미확인 |
| 폭 0.35 m 미만 통로 | 통과 불가로 판정. 대회 맵의 문 폭 확인 필요 |
| 회전 시간 | 비용에 포함하지 않음. 시간 점수가 있으면 [시간 최소 경로 가이드](../../how-to/sar-시간최소경로-가이드.md) 2장 검토 |
| 프론티어 목표 변경 억제, 회전 부담을 고려한 목표 선택 | 구현하지 않음. 목표를 유지하고 경로만 재계획하는 미션 정책으로 대응 |
| 사과 위치의 통행 금지 | 지도에 사과가 없어 경로가 구조 완료한 사과 위치를 지날 수 있음. 가상 장애물 등록 기능 없음 |
| 로봇 위치가 장애물 칸 안일 때의 탈출 방향 | 가장 가까운 유효한 통과 가능 칸 방향. 얇은 벽에서는 방향을 구분할 수 없음 |
| `logodds`·`seen` 직접 수정 | `invalidate()`를 호출하지 않으면 이전 계산 결과를 재사용 |
| 계산 방식 | Python `heapq`. 확인 영역이 넓어질수록 시간이 증가하므로 호출 주기 제한을 지켜야 함 |
