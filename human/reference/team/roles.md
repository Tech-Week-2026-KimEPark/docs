# 역할과 담당 범위

팀 4명의 역할, 담당 모듈, 백업 짝을 정리한 문서입니다. 원본은 [전체 묶음 요약본](../sar-전체-묶음.md) 5부의 역할 카드입니다. 담당 모듈 경로는 sar-robot 저장소 기준입니다.

## 역할 배정

| 역할 | 담당자 | GitHub | 백업 짝 |
|---|---|---|---|
| A 리더·통합 | 미정 | 미정 | B |
| B 탐색·경로 | 미정 | 미정 | A |
| C 인식 | 미정 | 미정 | D |
| D 제어·테스트·발표 | 미정 | 미정 | C |

담당자가 확정되면 이 표를 갱신하십시오. GitHub 계정이 확정되면 sar-robot에 `CODEOWNERS`를 추가해 담당 모듈의 리뷰어를 자동 지정합니다.

## 담당 모듈

| 역할 | 담당 업무 | sar-robot 담당 경로 | 대회 중 산출물 |
|---|---|---|---|
| A | 규정·채점표 해석, 주최측 질문, CONTEXT.md, 장치 연결, 상태 머신, 통합, 스코프 축소 결정 | `src/sar/mission/`, `src/sar/robot_io.py`, `src/sar/config.py`, `controllers/` | 통합 코드, git 태그, 제출 패키지 |
| B | 좌표·격자 지도, 프론티어 탐색, A\*, 목적지·복귀 경로 | `src/sar/mapping/`, `src/sar/planning/`, `src/sar/geometry.py` | 지도·경로 코드, 지도 시각화 |
| C | 대상 검출, 오탐 방지, 대상 월드 좌표 계산, 조명 튜닝 | `src/sar/perception/`, `models/` | 인식 코드, 색 임계값 기록, 인식 화면 |
| D | 속도 명령·경로 추종, 비상 정지, 위치 추정 보정, 성능 측정, 반복 테스트, 발표 | `src/sar/control/`, `src/sar/localization/`, `worlds/` | 제어 코드, 테스트 기록표, 데모 영상, 슬라이드 |

`tests/`는 해당 모듈 담당자가 작성합니다. `docs/`는 변경한 사람이 같은 PR에서 갱신합니다.

Webots 3D 시뮬레이션 형식(S2)의 역할 비중은 다음과 같습니다.

| 역할 | S2 중점 작업 |
|---|---|
| A | RobotIO의 장치 이름·좌표축 확인 |
| B | 격자 지도, 프론티어, A\* |
| C | 카메라 검출 |
| D | 좌표축·속도 측정, 경로 추종 제어 |

## 파일 수정 원칙

- 파일 1개는 담당자 1명이 수정함
- 다른 역할의 파일을 수정해야 하면 담당자에게 요청하거나 담당자를 PR 리뷰어로 지정함
- 모듈 인터페이스를 바꾸는 PR은 사용하는 모듈 담당자 전원의 확인을 받음
- 백업 짝은 상대 모듈의 동작을 설명할 수 있어야 함. 담당자가 작업을 진행하지 못하면 백업 짝이 인수함
